## 二、外壳模型：全局只有一级导航

```
┌────────────┬──────────────────────────────────────────────────┐
│ 导航栏      │ 工作区                                            │
│ 216px      │ （模块内部允许再有自己的列，但那不算"第二级导航"）    │
│            │                                                   │
│ 品牌        │  页头：标题 + 角色上下文 + 数据来源与时间            │
│ 玩家工作区   │  ────────────────────────────────────────────    │
│  聊天       │                                                   │
│  仓库       │  模块内容                                          │
│  配装       │                                                   │
│  配装槽     │                                                   │
│  任务随航    │                                                   │
│  成就       │                                                   │
│  收藏       │                                                   │
│  角色       │                                                   │
│  活动       │                                                   │
│ 账号与工具   │                                                   │
│  工具/设置   │                                                   │
│ 账号区      │                                                   │
└────────────┴──────────────────────────────────────────────────┘
```

三条硬规矩：

1. **导航栏只有一套，切换只换工作区。** 底层是 `app.css` 的
   `.app-shell { grid-template-columns: var(--nav-width) minmax(0,1fr) }`（`--nav-width: 216px`）。
2. **模块内部的第二列属于工作区，不是全局导航的第二级。** 老页面的聊天就是
   `.chat-layout { grid-template-columns: var(--session-width) minmax(0,1fr) }`（280px 会话列）。
   所以"聊天 = 会话列 + 对话"是工作区自己的事，导航栏不用变成两级。
3. **导航分组保留原来的三个语义**：`玩家工作区`（Destiny 内容）、`账号与工具`、底部的账号区
   （守护者头像 + BungieName + 绑定状态 + 菜单）。这三块在 `AppShell.tsx` 里已经长这样了。

**为什么不做两级导航**（图标栏 + 二级面板）：8–10 个模块用一级就够，二级会把 1280 宽的窗口压成
三列，装备页就没地方了；而需要"筛选/树"的模块（装备、成就）本来就该把那一列放在工作区里，
贴着它服务的数据。

## 三、页头：Destiny 的上下文必须常驻

Destiny 里**一切都按角色算**（装备、任务、配装、活动），所以页头固定三段：

```
标题 · 副标题            [角色切换：猎人 光等 2013 ▾]  [数据来源 · 时间]  [刷新]
```

- **角色切换器**放页头而不是全局标题栏：它是页面级上下文，换页面跟着换；
- **数据来源 + 时间**放页头右侧：这是"这条数据是几分钟前的"的唯一出口，
  它同时也是写入前的安全提示（数据太旧就别写）。

## 四、Agent 与工作区的关系（这次真正的新问题）

老页面里聊天是主站，其他页面是附件。新形态里聊天只是**九个模块之一**，所以必须回答：
Agent 和确定性 UI 之间是什么关系。三条，按优先级：

1. **Agent 是一个模块**（导航第一项），不做成唯一入口 —— 这条来自设想里那条原则：
   确定性的事由程序算，别让 Agent 成为唯一操作方式。
2. **工具结果不是一段文字，是一个带来源的块**（原型里的"候选拆解 · 3 件"）：
   模型只解释，UI 由 schema 决定（老页面 `webui-next-message-rendering.md` 的规矩，
   理由写着三条：XSS、模型会漏闭合标签、同一结果每次排版不同）。
   块头必须带 `账号 / 图鉴 / 社区` 标签与时间；块尾给一个**跳回对应工作区的按钮**
   （"在仓库里打开"）。
3. **写入确认是一等公民，不是聊天里的一句话**：`准备执行 · 3 步` 那张卡列出每一步和"为什么"，
   主按钮才是执行。确认卡与工作区里的操作共用同一份服务端签发的候选
   （`execution_id`），所以"从聊天里执行"和"从仓库页执行"是同一件事，不会有两套逻辑。

**待你拍板**：聊天右侧要不要常驻一个"Agent 正在看"面板。
老页面的 `DESIGN.md` 写的是 *"右侧或未来的工具面板应保持可选，未挣到位置前不显示"* ——
按这条我**没有**在原型里放常驻右栏；需要的话把它做成可折叠的第三列。

## 五、数据可信度必须长在 UI 上

这是这个产品区别于 DIM/Braytech 的地方：**数据分档不许混**，那就得在界面上看得见。
原型里做成一套复用的 `来源标签`：

| 标签 | 用在 | 颜色 |
| --- | --- | --- |
| `账号 · 2 分钟前` | 背包、任务进度、成就进度 | 绿 |
| `图鉴 · 已核对` | Manifest 定义、地图节点坐标 | 青 |
| `社区 · Starside · 2026-09-21` | 攻略片段、清单、评分 | 黄 |
| `人工整理 · 2026-09-28` | 任务步骤文案、周常周期表 | 金（强调色） |
| `未核对 / 没锚点 / 未写入` | 不确定状态 | 红 / 暗灰 |

**规矩**：任何一个数据块，如果不带来源标签，就是漏了。特别是社区与人工整理这两档 ——
它们会过期，界面上必须能看出"这是谁什么时候给的"。

## 六、装备页（老页面那半的直接延续）

形状照 DIM 与老页面：**角色/仓库做列，槽位做行**。尺寸全部来自 `inventory.css`：

| 项 | 值 |
| --- | --- |
| 导航栏 | 216px |
| 角色列宽 | 169 / 191 / 213px（三档断点）；原型取中间偏宽 186px |
| 物品格子 | 48 / 54 / 60px；行高 76 / 82 / 84px |
| 空位 | 42 / 48 / 54px |
| 桶内边距 | 8 / 10 / 11px，行距 6–8px，列距 4px |
| 桶最小高 | 92 / 102 / 106px |
| 侧板 | 10px 拖拽条 + 可调宽面板（`inventory-panel-resizer`） |

设计要点：

- **桶里用 flex 换行，不要用 grid + `grid-auto-rows`**：第一版原型用了 grid，
  结果标题行也被算成 76px，物品行之间空出一大段（原型里已修，注释留在 CSS 里）。
- **不一次倒出**：仓库 587 件，用 `还有 30 件 · 展开`；列表只渲染可见区域。
  这条对应后端那条实测（列 1260 件 ≈ 511 KB ≈ 13–15 万 token）。
- **物品格子上的颜色只表示稀有度**，左侧一条色带 + 已装备/已锁定两个角标；
  已装备用强调色描边 + 金点，已锁定用黄色色带。
- **空位要画出来**：`2/9` 这种容量感是 DIM 体验的一半，空槽不能省。

## 七、任务随航页

第一版只做一条链：**当前任务 → 当前步骤 → 当前目标 → 去哪 → 怎么做**。

- 步骤号与进度来自账号（组件 301 实测能读，见 [PERSONAL_CLIENT_PLAN](../plans/PERSONAL_CLIENT_PLAN.md) 3.1）；
- 步骤文案标 `人工整理 · 日期`，并且页面底部有一条**不许模型现编**的说明；
- 地图只画**导演地图**那一层（目的地 → 活动图节点，Manifest 里真有 `position {x,y}`），
  图例里明写"关卡内路线：无数据（靠人工整理）"—— 把做不到的事画在图上，比藏在文档里诚实；
- "接下来"那一行标 `没锚点 · 只给候选`，沿用周常轮换那套口径（ADR-010）。

## 八、密度与色板

token 直接抄 `tokens.css`（不重新发明）：

```
底       --bg #090a0c      --bg-raised #0d1013
面板      --surface-1 #101317  --surface-2 #14181d  --surface-3 #1a2026
线       --line #2a3037    --line-soft #1d2227   --line-strong #3a424b
字       --text #e8e9e6    --muted #9fa6ac       --text-strong #fafaf7
强调      --accent #d7b35e（hover #e4c370，soft rgba(215,179,94,.11)，ink #17130b）
冷色      --cool #7bb0b5（元信息、链接）
语义      success #7fb58b  warning #d5a85f  danger #dc7979  focus #e5c675
圆角      xs 5 / sm 7 / md 10
字体      Inter + PingFang SC（界面）· Georgia（助手正文与攻略）· SF Mono（数字/ID/hash）
```

**金色冲突要处理**：强调色是金 `#d7b35e`，而游戏里异域物品也是金。规矩是
**金色只做界面（激活态、左边框、主按钮），物品色只做物品**（格子左侧色带），
并且把稀有度金压暗一档（`#b8933f`），避免"这个高亮是强调还是异域"分不清。

主题：`tokens.css` 已经有 `data-color-theme` 的四套（金 / abyss 青 / crimson 红 / frost 蓝 + light）。
Flutter 侧照抄成 theme 开关即可，不要重挑一套配色。

## 九、状态覆盖（不能只有成功态）

每个模块至少四态，原型里能看到的：

| 状态 | 表现 |
| --- | --- |
| 正常 | 有数据 + 来源标签 |
| 空 | "还没有配装" + 一句怎么产生（不是空白页） |
| 未核对 | 红/灰标签 + 说明"哪一步没查" |
| 加载 | 骨架屏（照最终形状，不用转圈） |
| 写入回执 | 成功 / **未确认**（写了但回读不到，3~10 秒同步窗口）/ 失败（说清停在哪一步）/ 需要选一件 |

"未确认"这一档必须单独设计：它不是失败，也不能画成成功。

## 十、Flutter 落地映射

| 这里 | Flutter |
| --- | --- |
| `tokens.css` 变量 | `ThemeData` 的 `ColorScheme` + 自定义 `ThemeExtension`（一套 token，别散在组件里） |
| 216px 导航栏 | `NavigationRail`（labelType: all）或自绘 `Drawer` 常驻 |
| 工作区切换 | `IndexedStack` 保活 —— 聊天切走再回来不能丢流式输出 |
| 会话列 / 侧板 | `Row` + `ResizablePanel`（10px 拖拽条） |
| 虚拟化列表 | `ListView.builder`；仓库 587 件必须虚拟化 |
| 正文衬线 | 打包 Georgia 的替代（如 Noto Serif SC）并设定 fallback |
| 命令面板 | `⌘K` → `Shortcuts` + `Overlay` |
| 四态 | 每个页面的 `AsyncValue` 分四个分支渲染 |

## 十一、待你拍板

1. **导航第二项叫「仓库」还是「装备」**：老页面叫仓库，但那页其实包含三个角色身上的装备，
   叫仓库是窄了。改主标签会影响肌肉记忆，所以留给你定。

   原型照做了；如果你想要常驻，我加可折叠第三列。
3. **默认主题**：金（现状）/ abyss 青 / crimson / frost —— 沿用老页面的默认金即可，确认一下。
4. **导航里 9 个 Destiny 模块会不会太多**：原型全放了；如果第一版只做 5 个，
   告诉我砍哪几个（我的建议：先 聊天 / 仓库 / 配装 / 任务随航 / 成就，其余进"更多"）。
