## 2.5 「他们是怎么排表的」（2026-09-21 查证）+ 停更带来的结论

- **Braytech 的轮换表不在客户端里**：它的前端只调用自己的后端 `b.vlsp.network`
  （`/Common/Parameters`、`/Xur/Update`、`/Transform/Trials`、通知相关），**没有**轮换服务；
  客户端里唯一和失落区域轮换有关的东西是一个**用户可填的参数** `rotationLostSectors`
  （形如 `[hash,hash],[hash,hash]` 的每日列表，用来驱动它自己的推送通知）。
  也就是说：连 Braytech 都没有"权威机器可读来源"，**这张表是人工维护的**。
- 它的前端渲染"今天是哪个失落区域"时，是从一个**活动对象**上取
  （`activityTypeHash === 103143560`，再取 `DestinyActivityModeDefinition[103143560]` 的名字）——
  说明它也是"拿到活动 hash 再查 Manifest"，跟我们要做的一样。
- **游戏停更 → 表不会再漂**：锚点核对一次就变成永久常量，风险从"会过期"变成"核对时别错"。
  这正好是硬编码周期表的最佳时机（周期本身不再变化）。

**要把表钉死，只差一次游戏内核对**（一次性输入，之后永久有效）：

| 轮换 | 需要你给的"今天是谁" | 已有 |
| --- | --- | --- |
| 上维挑战（6 周循环） | — | ✅ 截图已给完整循环与锚点（8/12 衔尾蛇 → 9/23 衔尾蛇） |
| 异域任务轮换（7 周循环） | — | ✅ 截图已给 7 条日期（9/9 安可 → 10/21 苦命鸳鸯） |
| 传说/大师遗失区域（每日） | 今天/今天前后的两个名字 | ❌ 待给 |
| 夜幕 / 宗师（每周） | 本周是哪个打击 | ❌ 待给 |
| 泉源（每日 攻击/防御） | 今天是攻击还是防御 | ❌ 待给（截图里有 9/16–9/22 的日列表，可作锚点） |

## 2.6 夜幕/宗师：API 有；遗失区域：确实没有（2026-09-21 实测）

**夜幕/宗师在组件 204 里**（`characterActivities.availableActivities[]`，本周实测）：

| 条目 | 词缀（`modifierHashes` → Manifest 名字） | 掉落（`visibleRewards`） |
| --- | --- | --- |
| 切除: 宗师 | 宗师修改器 / 团灭 / 有限复活 / 勇士敌人×2 / 护盾敌人×2 / 电弧激涌 / 缚丝激涌 | 故我在、故我在催化、上维碎片（普通） |
| 日落: 大师 | 大师难度修改器 / 装备锁定… / 电弧威胁 / 随机祸因 / 流星 / 狂热 / 火刑 / 戏弄 | 异域装备、强化棱镜、上维碎片、日落武器 |
| 日落: 专家 / 高级 | 各自的词缀（专家修改器、高级修改器…） | 各自档位的奖励 |

→ 「本周夜幕/宗师是什么 + 词缀 + 掉什么」**不用维护表**，读组件 204 就有。
（词缀**描述**里有 `{var:...}` 变量，显示时只给名字、不猜数字；要插值再挖常量表。）

**遗失区域不在 API 里**，三条独立证据：
1. `/Destiny2/Milestones/` 的 12 条与 31 条里程碑定义里都没有它；
2. 组件 204 的 **294 个 `availableActivities` 里一个遗失区域都没有**（按 `activityTypeHash == 103143560` 过滤为空）；
3. Manifest 里那个「遗失区域」**清单**（hash 3142056444，42 条，在**角色级**组件 202）是"打过/解锁了哪些"——
   本账号实测 **42/42 全完成** —— 它**不是**"今天轮到哪个"。

**顺带挖到一块没用过的数据：清单（checklists）**
- 档案级（组件 **104**）19 条：地区宝箱、猫雕像、腐化的卵、阿罕卡拉遗骨、死去的机灵（月球）、企鹅纪念品…
- 角色级（组件 **202**）3 条：遗失区域 42/42、玉兔 2/9、永恒远古头骨 0/7
- → 「这些收集品我还差哪几个」是**零新增端点**的功能（组件 104/202 本来就要读），可以先记进候选。

| 异域任务轮换 | **自维护表**（7 周循环 + 锚点） | 名字 + 该任务的「标准」活动 hash（Manifest 取，注意同名重复） | 表 | 安可 `2880643894`、前兆 `3883295757`、暗屋之声 `2668737148`、行动：炽天使之盾 `1221538367`、苦命鸳鸯 `196691221`… |
| 泉源 | **自维护表**（日循环，攻击↔防御 交替 + 锚点） | 名字（攻击/防御 × 标准/专家/大师）+ hash（**同名有重复 hash，要挑定一个**） | 表 | `泉源：攻击: 标准` `54269080`/`201280774`（重复）；截图日列表 9/16 攻击 → 9/17 防御 → … |
| 遗失区域 | **自维护表**（31 个地点顺序 + 锚点） | 地点名 + 专家/大师 hash | 表 | 101 条活动 → **31 个地点**（K1后勤区等，含 专家/大师/传说 变体与重复 hash）；⏳ 等一次游戏内"今天是谁" |

**原始数据里要处理掉的坑（开工前记下）**：
1. 词缀列表里**有空的 `modifierHash`**（本周宗师第一条是 `""`）→ 渲染时跳过空项，不输出空名字。
2. `phaseHash` 全为 `null`；里程碑里**没有 `challenges`**（本周 12 条全空）→ **不做"本周突袭挑战"**，别硬凑。
3. 宗师/夜幕的**打击名**来自那一条的名字（`切除: 宗师`）；如果哪天上游给的是泛化的 `日落: 宗师`，就如实说"上游只给了难度、没给打击名"，**不编**。
4. 三个角色的 `availableActivities` 日落/宗师四条**完全一致**（已实测比对），所以按任意角色读一次即可。
5. `visibleRewards` 里的数量可能是 `0`（占位）→ 原样给，别当成"掉 0 个"。
6. 泉源/异域任务/遗失区域都有**同名重复 hash**（历史版本）→ 表里存"挑定的那一个"，并在注释写明挑的标准（带 `标准` 后缀的优先）。

## 3. 设计

### 3.1 intent 与参数
- `world_assistant(intent="rotations")`，别名 `轮换`/`周常轮换`/`这周`（放 world 面，和 `weekly` 并列：
  `weekly` 答"本周概要"，`rotations` 专答"轮换表"）
- 参数复用已有归属：`mode`（nightfall/lost_sector/ascendant/wellspring/exotic/raid/all，留空=全部）、
  `count`（往后看几天/几周，默认 7 天）

### 3.2 响应形状（每行一条）
```json
{"date": "2026-09-23", "week_of": "2026-09-22T17:00Z", "kind": "ascendant_challenge",
 "name": "衔尾蛇", "activity_hash": 0, "modifiers": [],
 "source": "schedule", "schedule_revision": "2026-09-21", "confidence": "核对过"}
```
- **官方给的**标 `source: "official"`（突袭/地牢，附官方 `startDate`/`endDate`）；
- **周期表算的**标 `source: "schedule"` + `schedule_revision`（最后一次核对日期）；
- 表里锚点超过 8 周没核对 → 降级 `confidence: "可能已过期，以游戏内为准"`。

### 3.3 红线（诚实口径）
1. 官方没给的一律标 `schedule`，**不许写成官方数据**；
2. `{var:...}` 没插值就原样显示，**不猜数字**；
3. 锚点过期要自己说出来，不装作还准；
4. 周期性内容会随版本变（Bungie 改顺序就得改表）——这句话要进响应，不能只写在文档里。

## 5. 待拍板（默认值）

1. **范围**：先做「官方那半 + 夜幕/宗师词缀」（默认）／一次把 6 类轮换全做（周期表都要能核对）

3. **锚点维护**：写在 `data/rotations.py` 里带核对日期（默认）／单独一份可手改的 YAML（方便你自己改）

## 5.5 已知前提

游戏已停更（内容不再变）：周期表核对一次即可长期使用；表里每条都要带 `verified_at`（核对日期）
与 `verified_against`（怎么核的：游戏内截图/玩家确认），未来任何人想改表都能看到依据。

## 6. 明确不做

- 不猜"今天是谁"：没有锚点的轮换（梦魇狩猎、扭曲）先不做，等能在游戏里核对出来再说；
- 不抓第三方网站当数据源（Braytech/light.gg 的轮换表是别人的产物，引用可以，抓取代跑不合规矩）；
- 不因为轮换表过期就静默给旧答案（要么降级说明，要么拒答）。
