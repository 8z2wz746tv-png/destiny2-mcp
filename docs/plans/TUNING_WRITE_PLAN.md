# 代写调谐（Tuning）开放方案

**目标**：让「确认后就替你改」覆盖调谐 —— `equip_build` 与 `equip_mod` 能像装护甲模组一样
把调谐也写进去，方案真正一键落地，用户不必再进游戏手点。

**为什么现在才做**：这条能力被两代错结论挡住了两次（1663 字段名 bug → "只能游戏内改"；
"只能换成你已经拥有的那一颗" → 2026-09-22 真机纠正为"**只能换成这件护甲允许的那几颗**"，
权威出处是组件 310）。2026-09-22 用真机跑通了完整往返：四件护甲的调谐通过免费插槽接口
写入，`ErrorCode=1`、回读插槽与六维一致、**不花材料**。所以障碍只剩"我们没开这条路"。

## 一、口径（三条硬规则，先定下来）

1. **只写"这件护甲允许的那几颗"**（组件 310 的清单）。不在清单里 → 不写、如实说明
   （上游会回 1675 `DestinyCannotAffordMaterialRequirements`，那句读作"这颗装不到这件上"）。
   这条在**生成候选时**就要拦住：`canonical_build` 里不许出现装不上的调谐。
2. **调谐并入可执行计划**：`CanonicalBuild.items[].mod_sockets` 里带上"调谐槽号 → 目标插件"。
   理由：调谐槽本来就是插槽，执行器、回读、失败处理都能复用同一条路，不新增第二套写入机制
   （新增字段等于新增一条可能跑偏的路）。能量恒为 0，不占模组预算。
3. **写前必须 `confirmed=true`**（现有纪律不变）。**不自动回退**：回退也是写入，风险更大；
   失败时如实报"哪几件改了、哪几件没改 + 怎么重试"，由用户决定。

**实现说明（2026-09-22 落地时的两处务实调整）**：

- 调谐**并进 `LoadoutItem.mods`**（而不是 `mod_sockets`）：执行器对 `mods` 是"按插件类别找插槽"，
  而调谐类别本来就在 `_MOD_CATEGORY_HASHES` 里（`loadout_mod_sockets.py` 的注释写着"一直允许
  往调谐槽写"）。这样连索引字段都不用新增，回读也一视同仁 —— 比原方案更省。
- "清单外的调谐整条候选标记为不可执行"改成**不进计划**：求解器的选项本来就来自 310 清单
  （四·十四），正常路径下不会出现清单外的目标；写入前的过滤是**兜底**，命中时只少做一步、
  不把整条候选作废（更符合"能做的先做"）。
- **回读不用新写**：`_verify_loadout` 本来就逐个核对 `item.mods` 里的插件是否在插槽上
  （`any(mod_hash not in actual_plugs)`），调谐跟在 `mods` 里就自动被核对 ✓。
- **"写失败不回退"差点没成立**：执行器对"上游拒绝某一颗"与"硬失败"分两档 —— 前者记
  `steps.mod_blocked` 并**不回退**，后者回退。1675 原来**不在**"挡住"名单里（`mod_write_blocker`
  只认 1676/403/1663），于是一颗写不进去的调谐会连累整条配装被回退。已把 1675 加进挡住名单，
  并补了一条以前**没有测试**盖住的守门（`mod_blocked` → 不回退、也不报成功）。

## 三、守门（每条都要注入验证）

1. **清单外的调谐不许进候选**：夹具里造一件 310 清单只允许 `+职业/−X` 的护甲，
   候选若提出 `+武器/−近战` 必须被拒（生成期拦）——这是用户发现的那个 bug 的回归哨兵。
2. **`writable` 只看清单**：清单里有 → `writable=true`；没有 → `false` + 人话原因（含 1675 的含义）。
3. **`confirmed=false` 不写账号**（现有守门扩展一条调谐用例）。
4. **回读不符不许报成功**：调谐写入后回读插槽，对不上就报失败并把账号现状说出来。
5. **部分成功如实报**：5 件里改了 2 件时，响应必须写清哪几件成了、哪几件没成。
6. 语料：`sweep` 组里 `equip_mod` 的调谐行改成"可写"；`find` 的 `tuning_changes` 验收点改写。

## 四、验收（真机）

1. 拿现在这套（武器140 手雷140）故意把某件的调谐换掉一颗 → 用**新路径**一键改回来，
   回读插槽 + 六维与方案逐项一致；
2. 故意让它写一颗"不在清单里"的 → 必须被拒且账号不变；
3. 跑 `scripts/audit_armor_model.py`（468 件 + 29 个固定证人）保持全过；
4. 跑一次 `scripts/run_corpus_all_rows.py`（真机语料）。

## 五、不做

- 不做"自动降目标"（安全规则要求用户确认，现状不变）；
- 不做"替你花材料"的预检与采购：清单外的调谐会回 1675，如实报，不替用户判断"值不值"；
- 不做批量回滚（失败就停并如实报，回退由用户决定）；
- 不动 `equip_loadout` 的既有语义（它执行的是"用户已存的配装"，不带求解器规划）。
