# ADR-003: 实测优先于文档，冲突必须记下来

- Status: accepted
- Date: 2026-09-17
- Decision By: 用户（Husky）
- Scope: `docs/reference/bungie_api.md`、所有写上游对接代码的地方、AGENTS.md 的「遇到 Bungie API 问题怎么查」

## Context

对接 Bungie API 时，官方文档（<https://bungie-net.github.io/>）是**定义来源**，但它不保证
描述完整、不过期、也不描述权限细节。这个项目已经吃过两次亏：

1. **把文档读成了结论**：官方写"`InsertSocketPlugFree` 覆盖 Perks, **Armor Mods**, Shaders,
   Ornaments"，我们就据此推断"护甲模组不需要 `AdvancedWriteActions`" —— 真机三次实测证明
   没有该 scope 时 free 接口同样写不进去（1663 "This action can only be done in-game."）。
   文档讲的是**接口语义**，我们读成了**权限要求**。
2. **文档没说的事只能靠实测**：只请求组件 `305` 时上游一个插槽都不返回（实测 0 件带插槽，
   带上清单类组件 1627 件）；写入成功后 profile 有 3～10 秒的同步窗口（`EquipItem` 回
   `ErrorCode=1` 后立刻回读仍是旧值）。这两条文档里都没有。

**What changed** —— 早期口径是"以文档为准"；现在改为"文档给定义、实测给结论"。

## Decision

1. **实测优先**：官方文档与真机结果冲突时，**以实测为准**，并把它写进
   `docs/reference/bungie_api.md`（每条固定四段：事实 / 出处 / **实测** / 结论；口径声明在文件开头）。
2. **冲突要留痕**：发现冲突时，在对应条目里**明写"文档这么说、实测是那样"**，
   而不是悄悄按实测改掉 —— 下一个人需要知道这个坑在哪。
3. **引用必须可查**：写进代码注释、ADR、plan 的上游结论，要么给官方链接，要么给实测日期与结果，
   **不允许**只写"据说""经验上"。
4. **文档快照不进仓库**：官方文档体积大、会自动生成、会静默过期（页面自身带版本号，实测 2.21.8）。
   需要离线读原文时用 `scripts/fetch_bungie_api_docs.py` 拉到 `~/.destiny_mcp/reference/`
   （仓库外、带版本号与 sha256，`--check` 可看版本变没变）；仓库里只留我们自己的口径。
5. **不允许**：把推断写成事实；文档没写的细节凭印象实现；上游行为变了但不更新实测条目。

被否掉的方案：① 把官方文档整站镜像进 `docs/`（体积大 + 静默过期 + 再分发边界不清）；
② 只在代码注释里记结论（散、查不到，且没有"实测日期"这个关键字段）。

## Consequences

- `docs/reference/bungie_api.md` 成为上游问题的**第一入口**，它有维护成本：
  上游行为变化、或我们做了新的真机实验，都要回去更新对应条目（AGENTS.md 里已写明这条路径）。
- 真机验证的纪律被这条决定正式化：**先说改什么 → 写 → 回读核对**（写入许可见 ADR 之外的记录，
  账号写入需用户明确同意）。
- 有些结论会"看起来反直觉"（例如护甲模组必须游戏内装），但它们带着实测证据，比推测可靠。
