# ADR-NNN: 标题（一句话说清决定了什么，不要写成"关于 XXX 的讨论"）

- Status: accepted
- Date: YYYY-MM-DD
- Decision By: maintainer
- Scope: 受这条决定约束的文件或模块（可选，但改这些地方前应该先读到这里）

## Context

为什么要做这个决定：现状是什么、哪里会疼、有哪些约束（上游限制、账号安全、体量上限）。
外部事实要给证据（实跑结果、上游文档、报错原文），不要写"据说"。

**What changed** —— 相比之前变了什么：新发现的证据、被推翻的假设、上游的改动。
回溯补记的 ADR 要在这里说明"实现早于记录"。

## Decision

决定了什么。用能被执行的口径写：哪些类型/字段/流程是唯一入口，哪些做法**不允许**。
被否掉的方案也写在这里（否掉的理由），否则下一个人会再提一遍。

## Consequences

代价与后果：这条决定让什么变难了、哪些能力被排除、以后要改它得同时改什么（测试、文档、调用方）。
只写真实后果，不写愿望。
