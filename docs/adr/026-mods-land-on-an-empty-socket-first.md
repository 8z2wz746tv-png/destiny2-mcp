# ADR-026: 护甲模组的落点**空槽优先**，三格全满才顶人

- Status: accepted
- Date: 2026-10-06
- Decision By: maintainer
- Scope: `services/loadout_mod_sockets.py`（`_find_mod_socket` 的落点顺序）、
  `services/loadout_plug_lookup.py`（`socket_takes_plug`）、
  `services/armor_mod_service.py`（计划里的 `socket_index` / `from`）

## Context

护甲上有四个能装模组的位：`enhancements.v2_general`（属性模组，位 0）与三个部位模组位
（位 1/2/3，例如头盔的 `enhancements.v2_head`）。**三个部位位共享同一份 plug set** ——
也就是说，对"能不能插这颗"这个问题，三格的答案是**一样的**。

**What changed** —— `_find_mod_socket` 原来的落点顺序是：
① 哪一格已经装着这颗 → 用它；② **哪一格的 plug set 里有这颗 → 用它**；
③ 哪一格**类别对得上** → 用它。②③ 都是从 0 往上扫的**第一个**命中项。

因为三格共享 plug set，②在**第一位就命中**（位 1），于是：

- 落点永远是位 1（位 2/3 只在"同一批里前一颗已经把位 1 占了"时才轮得到 ——
  `assigned_sockets` 只活在**一次调用**内）；
- **更糟的是**：哪怕这颗模组**已经装在后头**（位 2），扫到位 1 时"plug set 里有这颗"也照样返回
  位 1 —— 把玩家留在位 1 的那颗**顶掉**，把同一颗模组从位 2 搬到 位 1。玩家看到的是
  "换成功了"，实际丢了一颗。这是真机上"越换越差"的来源。

顺带纠正一个容易想歪的事实：**空槽不是"没有插件"**。每一格默认装着插槽定义里的
`singleInitialItemHash`，那是一颗叫 **Empty Mod Socket** 的真插件，而且
**它的类别跟真模组一模一样**（实测：至高狂徒面具 位 0 = `1980618587`、
位 1/2/3 = `1078080765`，都写着 `enhancements.v2_*`）。所以"空着"必须按这个占位来认，
不能按"plugHash 为空"认，也不能硬编码某一颗 hash（每个部位类别一颗）。

## Decision

落点顺序改成：

1. **哪一格已经装着这颗** → 用它（原样重插会被上游回 1679，白花约 10 秒）；
2. **空着、而且这颗插得进的格子** → 用第一格这样的；
3. 都被占着 → 才顶第一格能插的；
4. 兜底：类别对得上的第一格（没有 plug set 的槽走这条，口径与改动前一致）。

"空着"的判据 = **这一格装着的就是插槽定义里的 `singleInitialItemHash`**（或 plugHash 为空）。
"能不能插"的判据抽成 `loadout_plug_lookup.socket_takes_plug`（空桶/占用桶共用同一份）。

**被否掉的方案**：

- *"加一个 `socket_index` 参数让调用方指定"* —— 把"选哪一格"推给模型，而模型看不见
  每一格里现在装着什么（它只能看见名字），结果是多一条瞎指定的路，治不了根。
- *"永远别顶人（三格全满就报错）"* —— 玩家要换一颗的那一刻没别处可放，这条路会把
  "能做的事"变成"报错"，而顶掉谁在确认信封里本来就写得清清楚楚（`from.name`）。
- *"按模组类别挑一格专门管它"* —— 三格是等价的，没有"属性位/功能位"这种分工可分。

## Consequences

- **单发也会铺开**：第一次落位 1、第二次落位 2、第三次落位 3（每次都挑空槽），
  不再需要"必须三颗一次性给"才能填满三格。
- **不再无谓顶人**：有空槽就绝不动别人占着的格。三格全满时仍然顶第一格 ——
  这是有意保留的兜底，**顶的是谁由 `plan.from` 说出来**（确认信封与回执里都有）。
- **`_find_mod_socket` 从两趟扫描收成一趟**（"已经装着"的早退在同一个循环里），
  模块行数因此没有增长：`loadout_mod_sockets.py` 517 → 510。
- 要改这条决定，得同时改：`_find_mod_socket` 的两个桶与顺序、
  `socket_takes_plug`、以及 `tests/test_armor_mod_unlock.py` 里的三条守门
  （空槽优先 / 已装着不动 / 全满才顶，三条都注入验证过）。
